# GARUDA KINGDOM — GOVERNANCE

> How the Kingdom is governed. This doc is **additive documentation**; authoritative rules live in
> `GARUDA_CONSTITUTION.md`, `docs/foundation/02-FOUNDER-GOVERNANCE.md`, `GARUDA_APPROVAL_MATRIX.md`,
> and `GARUDA_BIBLE/11_FOUNDER_DECISION_REGISTRY.md`.

## 1. Sovereign founder
- Founder (Praveen Mahawar) is the supreme authority. **Founder words are last.**
- No AI self-authorization. Every significant action is approval-gated and audit-trailed.

## 2. Approval matrix (summary)
- Reads and analysis: generally permitted (inspect-before-edit).
- Writes / sends / payments / deploys / destructive or irreversible actions: founder approval required.
- Defensive security inspection is explicitly allowed; offensive capability is prohibited.

## 3. Three-layer governance
1. **Constitution + founder locks** — highest authority.
2. **Master Inventory + Kingdom docs** — canonical structure, never contradicts layer 1.
3. **Evidence & recovery status** — every claim carries RECOVERED/PARTIAL/IMPLEMENTED/RECONSTRUCTED/UNVERIFIED.

## 4. Autonomy boundary
- Autonomous execution is permitted **within** governance. Autonomous never means uncontrolled.
- Discover→qualify→acquire→execute→deliver→accept→collect→learn→repeat is the revenue loop, but each
  significant step is founder-gated per the approval matrix.

## 5. Changes to this doc set
- Kingdom docs may be extended only as documentation; production architecture changes require founder
  approval and must pass the Constitution first.
